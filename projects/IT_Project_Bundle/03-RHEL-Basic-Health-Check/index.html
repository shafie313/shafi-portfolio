02 / LINUX / BASH / SYSTEMD

Red Hat Linux Administration

A Bash utility that records a read-only snapshot of a Linux host, including operating system details, uptime and load, memory, filesystems, block devices, a selected systemd service, IP addresses and the default route.

This is a script briefing, not a captured lab result. The source guide does not include sample host output or claim that the checks were run successfully.

01 / OBJECTIVE

Collect a basic host snapshot

Gather commonly useful Linux troubleshooting details into one timestamped text report. The script does not intentionally change system settings; it creates the report directory and file.

Environment

  • Bash on Red Hat Enterprise Linux or another Linux distribution.
  • Some commands may be missing on minimal installations.
  • The selected service defaults to sshd; another installed service can be supplied as an argument.
02 / RUN THE SCRIPT

Usage

From the project directory, make the script executable and run it. Running without elevated privileges is the recommended first step.

chmod +x rhel-health-check.sh
./rhel-health-check.sh

# Optional output directory and service name:
./rhel-health-check.sh ./reports sshd

The report is written as reports/linux-health-<timestamp>.txt by default. Open that text file to review the collected sections.

04 / IMPLEMENTATION

Report workflow

  1. Accept an optional report directory and service name, defaulting to ./reports and sshd.
  2. Create the output directory and a timestamped report file.
  3. Write host, OS, uptime/load, memory, filesystem, block-device, service and network sections.
  4. Print the report path so it can be opened for review.

Interpret results carefully. This is a diagnostic snapshot, not an automated repair or a definitive health verdict. Command errors can appear in the report when a command is unavailable.

05 / TROUBLESHOOTING

Common checks

  • If the output directory cannot be created, check the path and write permissions; the script exits with an error if directory creation fails.
  • If the service is not found or inactive, pass the name of an installed service as the second argument and review its status.
  • If systemctl is unavailable, the report records that condition.
  • On a minimal installation, review command output for tools that are not installed.
  • Run without sudo first; elevate only when a specific check requires it.
