04 / WINDOWS SERVER / ACTIVE DIRECTORY

Windows Server Active Directory Lab

A guided, isolated virtual lab for practising AD DS and DNS role installation, domain-controller promotion, organizational units, test users, security groups and a Windows client domain join.

This is a guided lab plan, not a completed deployment report. The PowerShell examples below come from the project guide; use disposable virtual machines, snapshots and lab-only credentials.

01 / OBJECTIVE

Practise basic domain administration

Build a small isolated domain, organize lab accounts, check group membership and verify that a client can find and join the domain.

Suggested virtual environment

  • Windows Server evaluation VM: static address 192.168.50.10/24.
  • Windows 10/11 client VM: 192.168.50.20/24, DNS set to 192.168.50.10.
  • Lab domain: adlab.test; this example is for the lab and not a public internet domain.
  • Use an Internal/Host-only virtual network and take VM snapshots first.
02 / DOMAIN CONFIGURATION

Server Manager workflow

  1. In Server Manager → Local Server, rename the server to a lab name such as DC01. In Windows network adapter properties, assign the suggested static server address and subnet.
  2. In Server Manager → Manage → Add Roles and Features, install Active Directory Domain Services and DNS Server.
  3. After installation, select the Server Manager notification flag and choose Promote this server to a domain controller.
  4. Choose Add a new forest and enter adlab.test. Set a strong lab-only Directory Services Restore Mode password, review prerequisites, install, and let the server restart.
  5. After restart, use Server Manager → Tools to open Active Directory Users and Computers and DNS Manager.
03 / IMPLEMENTATION

Organize users and verify the client

  1. In Active Directory Users and Computers, right-click the domain, choose New → Organizational Unit, and create Lab-Users and Lab-Groups.
  2. Right-click Lab-Groups, choose New → Group, create IT-Support-Lab, and select a security group with the Global scope.
  3. Right-click Lab-Users, choose New → User, and create a lab-only test user. Open the user's properties, choose Member Of → Add, and add IT-Support-Lab.
  4. On the client, open the network adapter's IPv4 properties and set DNS to 192.168.50.10. In DNS Manager on the server, confirm the lab DNS zone is present; on the client, use the network and domain settings pages to verify the connection before joining adlab.test with authorized lab credentials.
  5. Join the domain through Settings → System → About → Domain or workgroup (the exact wording varies by Windows edition), then restart if prompted.
  6. Sign in with the lab domain account. In Active Directory Users and Computers, open the group properties and Members tab to visually verify membership.

Safety: AD DS promotion and network changes can affect connectivity. Keep this work in a disposable virtual lab; do not use production accounts or passwords.

04 / COMMANDS & CONFIGURATION

Optional Active Directory PowerShell examples

These examples are documented in the project README. Run them in an elevated PowerShell session on the lab domain controller after AD DS is installed and the domain is available. Check for existing objects before running creation commands.

# Verify the lab domain and controller
Get-ADDomain
Get-ADForest
Get-ADDomainController -Filter *

# Create the documented lab OUs and security group
New-ADOrganizationalUnit -Name 'Lab-Users' -Path 'DC=adlab,DC=test'
New-ADOrganizationalUnit -Name 'Lab-Groups' -Path 'DC=adlab,DC=test'
New-ADGroup -Name 'IT-Support-Lab' -SamAccountName 'IT-Support-Lab' `
  -GroupScope Global -GroupCategory Security -Path 'OU=Lab-Groups,DC=adlab,DC=test'

# Prompt for a lab-only password; do not store credentials in a script
$Password = Read-Host 'Enter a strong lab-only password' -AsSecureString
New-ADUser -Name 'Lab User' -SamAccountName 'lab.user' `
  -UserPrincipalName 'lab.user@adlab.test' -Path 'OU=Lab-Users,DC=adlab,DC=test' `
  -AccountPassword $Password -Enabled $true
Add-ADGroupMember -Identity 'IT-Support-Lab' -Members 'lab.user'
Get-ADGroupMember 'IT-Support-Lab'

Configuration: The example domain is adlab.test; the suggested server/client addresses are 192.168.50.10/24 and 192.168.50.20/24, with the client DNS set to 192.168.50.10. Confirm the distinguished names match your own disposable lab.

05 / GUI ADMINISTRATION

Review domain objects in the management consoles

  • Use Active Directory Users and Computers to browse the domain tree and review the lab organizational units, test user and security group.
  • Open the test user's properties and use Member Of to inspect group membership.
  • Use DNS Manager from Server Manager's Tools menu to review the lab DNS zone.
  • On the client, use Windows Settings to review the network's DNS server and domain membership.

Existing objects: Before creating an OU, group or user, look for it in the management console. Reuse or review existing lab objects rather than creating duplicates.

06 / GUI TROUBLESHOOTING

Inspect the configuration visually

  • If the client cannot locate the domain, open its network adapter's IPv4 properties and confirm DNS points to the domain controller. Review the DNS zone in DNS Manager.
  • If a domain join or sign-in fails, return to Windows Settings and check the client's network connection, DNS server and displayed domain/workgroup status.
  • If an OU, user or group appears missing, refresh the domain tree in Active Directory Users and Computers and check the correct OU before creating anything again.
  • If a user lacks expected group access, inspect the user's Member Of tab and the group's Members tab.
07 / RESULTS, LEARNINGS & EVIDENCE

Capture after you complete the lab

The README defines verification evidence, but does not include executed results. No successful domain setup is claimed here. The documented learning focus is how DNS, OU placement, group membership and client configuration work together during a basic domain join. Collect your own evidence after completing the steps:

  • Server Manager showing AD DS/DNS installed.
  • Active Directory Users and Computers showing the lab OUs, user and group.
  • The test user's properties showing membership in the lab security group.
  • Windows client Settings showing its lab domain membership and network DNS configuration.
