03 / WI-FI / TCP/IP / SMB

Wireless Access Point & File Sharing

A practical home/office lab guide to configuring an access point, checking wireless client connectivity and testing local Windows file sharing with appropriate network and account permissions.

The source is a setup and troubleshooting checklist, not a completed configuration report. Router features vary by model and firmware; no working test result is claimed.

01 / OBJECTIVE

Connect wireless clients and share files locally

Configure a wireless access point or router, validate the client network settings, and test a local SMB share from a second client.

Environment and preparation

  • Record the router/AP model, firmware, LAN subnet, DHCP range and current configuration.
  • Back up the configuration if the device supports it.
  • For a dedicated access point, use the intended operating mode and avoid creating a second DHCP server or accidental double NAT.
  • Router USB storage is optional and depends on exact model and firmware support.
02 / ACCESS POINT CONFIGURATION

Set up wireless access

  1. Connect the access point in the intended mode. For a dedicated AP, the guide recommends LAN-to-LAN and disabling its DHCP service when the main router already provides DHCP.
  2. Set a unique SSID and WPA2-AES or WPA3 security with a strong, unique passphrase.
  3. Disable WPS if it is not needed and update firmware from the vendor.
  4. Connect a client and check the assigned IP address, subnet mask, default gateway and DNS.
  5. Check coverage in multiple rooms; note signal level, band, channel congestion and dead zones.
03 / LOCAL FILE SHARING

Configure and test an SMB share

  1. Use a trusted computer as the file server. Enable SMB sharing only on a Private/trusted network.
  2. Grant share access to specific users; avoid broad Everyone/full-control permissions.
  3. On a second Windows client, open File Explorer, select the address bar, and enter the share's network location using the file server's host name or local IPv4 address.
  4. Verify read and write behavior according to the permissions intended for the lab.

Windows GUI workflow

  1. On the file-server PC, open Settings → Network & internet and confirm the connection is set to Private only if this is a trusted network.
  2. Open Settings → Network & internet → Advanced network settings → Advanced sharing settings. Turn on file and printer sharing for the Private network profile.
  3. In File Explorer, right-click the intended folder, choose Show more options → Give access to → Specific people (labels can vary by Windows version), and select the intended lab account and permission level.
  4. On the second PC, open File Explorer and enter the share location using the server's host name or local IPv4 address. Sign in with an account that has permission if prompted.
  5. Open a test file to check read access. To verify write access, create a harmless test file only if the account is intended to have write permission; remove the test file afterwards.

Router USB storage: Consult the exact model's manual. A USB port alone does not guarantee SMB or other file-sharing support. Do not expose FTP, SMB or router administration directly to the public internet.

04 / COMMANDS & CONFIGURATION

Validate addressing, name resolution and the share

The guide calls for checking the Windows client configuration, gateway and DNS lookup, then accessing the share from a second client. These are verification examples to run in your own authorized lab; no output is supplied or claimed.

ipconfig /all
ping <default-gateway-address>
nslookup <approved-hostname>

# Open in File Explorer from a second client:
\\HOSTNAME\ShareName
# Or use the file server's local IPv4 address:
\\<server-ipv4-address>\ShareName

Configuration notes: For a dedicated AP, the guide suggests LAN-to-LAN and disabling its DHCP server when the main router already provides DHCP. Keep SMB on a trusted Private network and grant access to specific users.

05 / CONNECTIVITY CHECKS

Verify network settings in Windows

On the wireless client, open Settings → Network & internet → Wi-Fi → the connected network's properties. Review the assigned IP address, subnet mask, default gateway and DNS values.

Use the Windows network status page to confirm connectivity. If a web browser is part of the lab, try a known permitted site only after gateway and DNS settings appear correct. No test output is included in the source guide.

06 / TROUBLESHOOTING

Follow the documented checks

  • No IP address: check Wi-Fi association and the router's DHCP settings; make sure another device is not also handing out addresses.
  • Network connectivity works but names do not: review the DNS values in Windows network properties.
  • Internet works but the share does not: check subnet reachability, Windows Private network profile, appropriate firewall rules, credentials and permissions.
  • Router USB storage is not visible: check drive format, model/firmware feature support and whether the sharing service and protocol are enabled.
07 / RESULTS, LEARNINGS & EVIDENCE

Capture evidence after testing

The source README describes evidence to collect but contains no test results or screenshots. Record the results from your own authorized setup:

  • AP model and sanitized configuration screenshots.
  • A screenshot of the Windows network properties page showing client settings; redact public IPs and sensitive details.
  • Gateway ping and DNS lookup results.
  • File-share access from a second client, excluding personal data.
  • Coverage observations and a short troubleshooting log.

Key learning areas include isolating DHCP and DNS faults, confirming the client network profile, and checking SMB credentials and permissions separately from basic connectivity.
